# 选题、文案与分镜：有来源的编辑流程

使用范围：知识短片前期创作与返修。阅读[来源登记](editorial-sources.md)了解证据层级，成品示例见工具根目录 `editorial-examples/birthday/`。这是本工程对公开方法的适配，不是某位创作者的原版课程，也未通过受众实验验证。

## 1. 从观看后的变化开始选题

先写四件事：谁来看、已经知道什么、可能在哪里误解、看完能解释或判断什么。最后一句必须能用一道新问题检验，例如“区分任意一对碰撞与固定对象匹配”，不能只写“了解概率”或“提升认知”。依据E1；以下候选卡为本工程设计。

每个候选有：

| 字段 | 填写内容 |
|---|---|
| 主问题 | 能用一口气问完的具体问题 |
| 开场观察 | 观众可以看见或尝试的情境；不预设所有观众都答错 |
| 一句话答案 | 包括不可删的适用条件；否则缩小题目 |
| 可展示的证据 | 能手算、模拟、查看原始资料或演示的核心环节 |
| 视觉关系 | 要表达比较、空间、数量、因果、时间、路径还是概率 |
| 解释差异 | 与常见解释相比，具体多提供了什么理解工具 |
| 来源就绪度 | 已读一手来源 / 只有二手 / 尚待研究 |
| 主要失败风险 | 例如把示意当实测、把局部结论外推到人生建议 |
| 预算与取舍 | 核心镜头可否在现有工具中准确表达；太难就换表达或缩小范围 |

用“已就绪、需补证据、不适合当前形式”分组并解释，不用假精确总分宣称某题会火。证据不足或核心画面不能解释，是暂缓理由。熟悉度、视觉可行性、差异化和成本可以比较，但不是预测模型。用户已经选题时不重新强迫其从候选选择。

## 2. 为题目选讲解路径，而不是套万能故事

| 路径 | 适用问题 | 组织方法 | 不适用时 |
|---|---|---|---|
| 构造与发现（E1、E3的适配） | 规则可手算或逐步演示 | 具体任务 → 尝试 → 观察规律 → 解释 → 新例子检验 | 仅凭动画无法证明，需要外部实证的结论 |
| 机制追踪（E2的适配） | 一个输入怎样变成输出 | 可见结果 → 最小机制 → 中间步骤 → 改变一个条件 → 边界 | 核心机制尚不清楚，只有相关性时 |
| 误解辨析（E4的有限借鉴） | 有来源支持的常见概念混淆 | 提供预测机会 → 对比两个问题 → 展示证据 → 修正解释 → 迁移题 | 为制造冲突而虚构错误直觉时 |
| 问题驱动的历史线（E6的适配） | 后一个方案确实解决前一个问题 | 未解问题 → 尝试及局限 → 新证据/工具 → 当前答案 | 仅是人物年份清单、两分钟塞入整部学科史时 |

可以组合，但要指出哪条推理是主线。不要把某本书、名人、诺奖放进每一个开场；它们只有在直接支持片中事实时才有用。知识结论不强接爱情、成功或自律金句。

## 3. 先做主张图，再写字幕

建立 `claims` 或独立事实表：说法、证据位置、模型条件、不能推出的结论、目标字幕。数字由计算或原始来源产生；模拟需存种子和结果，不能挑一次“正好很震撼”的结果冒充必然。

把论证画成文字依赖链：A让观众看见什么，B用到了A的哪条结果，C为什么能因此成立。找出全片最难的一跳。术语、公式和历史通常在观众需要它们时才出现；精确定义若是理解的前提，则先给最小定义，不为“先演后说”牺牲正确性。

例子与规律分开：一个生日配对图可说明比较对象很多，不能独自证明50.7%；该数值仍需精确补事件计算。

## 4. 字幕稿与视觉方案共同迭代

每个段落写“观众目前知道什么 → 新增什么 → 还欠一个什么解释”。先解决论证，再润色句子。可尝试两个不同开头并按可兑现程度选择，而不是简单选最刺激的标题。

编辑分四种检查，次数按问题决定：

1. 事实：所有定量说法、因果词和边界能否对上证据？
2. 推理：删除一段后结论还成立吗？该段若只提供气氛，缩短或删去。
3. 语言：抽象名词是否已落到对象/关系？代词指向是否清楚？一个长句是否同时塞了多个新概念？
4. 时间：屏上读字、寻找对象、理解变化的时间是否同时挤在一秒里？

无旁白时，音乐不替代文字信息。字幕不能按朗读速度估时。引擎的每秒7字符警告只是粗筛；较短字幕也可能因复杂图表而来不及理解。起稿可以先给约数秒，再通过实际小尺寸观看调整；不设置放之四海皆准的字数或留白百分比。（E5、E6）

不要求每句都配新动画：给定义、暂停提问或确认结论时，可以保留当前图形。不要为“每句一个动作”制造干扰。

## 5. 分镜表要能暴露推理缺口

建议逐拍填写下列字段；一镜可以跨多句，一句也可分多拍。字段可合并，但不能漏掉关键关系。

| 字段 | 需要回答 |
|---|---|
| 时间、字幕、主张ID | 谁在何时说什么，哪里有来源 |
| 叙事功能 | 提问、给条件、提供证据、解释、命名、边界或迁移 |
| 入镜状态 | 观众从上一拍带来了哪些对象和知识 |
| 对象与语义 | 谁代表什么；颜色、形状和单位是否一致 |
| 变化及关系 | 哪个对象发生什么变化，表达什么关系 |
| 观众应观察到的结果 | 看见了哪些可指认的差异或顺序 |
| 可以得出的推理 | 该观察支持什么；什么仍未被证明 |
| 注意与时间 | 阅读时是否还有其他主体抢动；给多少观察与停顿时间 |
| 出镜状态 | 交给下一拍的对象、问题与过渡 |

分镜不是给文案配关键词图片。讲“增加”要有一致标尺，讲“交换”要保留身份，讲“导致”要有机制或实证依据。拓扑用节点边、分布用图表，都是合适表示；不要求所有概念都拟物化。比喻写出对应与失效处，不能把视觉相似当机制相同。（E7的适配）

先测最难的解释镜头，再测开头。前者决定能否讲清，后者决定承诺是否清楚。转场优先保留同一对象或标尺；硬切可用于明确的对照，不为“丝滑”扭曲对象关系。

## 6. 从纸面走到样片的验证

先做能表示对象、变化和字幕时序的粗版，允许灰盒和简单线条，不先花时间堆辉光。检查三种阅读：只读文字能否理解论证；只看关键画面能否认出关系；合起来是否互相帮助。有些边界必须靠文字，不能把“遮字幕也全懂”设为万能合格线。

编辑自查可以指出漏洞，不能冒充观众测试。条件允许时给未参与制作的人看片后问：

- 片中主要在回答什么？
- 为什么会得到那个结果？
- 换一个条件后，哪些结论不再适用？

记录回答而非只问“好不好看”。若尚无受众，则明确“仅完成内部桌面检验/样片检查”，不得填写理解率或独立评审通过。自动检查只能筛结构、时间、引用和部分画面问题，不能认证讲解效果。

## 7. 发布后的学习闭环

保存版本、标题承诺、核心镜头、预期误解、改动和实际反馈。留存下跌与回看峰值都只是排查位置，回看不必然表示精彩；再看评论、理解题或访谈。平台差异和样本量都应记录。没有后台数据就不猜完播率，不用单条成功证明因果。（E10）

用一个真实问题改一条规则，保留反例；不要积累成越来越长的固定格式清单。学习沉淀在本项目文件，不自动写入用户全局记忆。
